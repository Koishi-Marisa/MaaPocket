# Kivo Wiki 角色资料与创作依据

## 服务信息

- Base URL: `https://kivo.xiaowan.dpdns.org`
- MCP: `https://kivo.xiaowan.dpdns.org/mcp`
- 数据来源: `https://kivo.wiki`
- 范围：搜索索引覆盖国服已实装角色（237 条，含皮肤形态）；未实装角色在本地无结果时会回退到站内搜索。详情支持任意角色 ID，未在国服实装的角色会返回资料并标注状态。

## 在 DSH 中使用

- 项目级安装：把本目录放到 `<项目根>/.agents/skills/kivo-wiki/`。
- 用户级安装：把本目录放到 `~/.agents/skills/kivo-wiki/`。
- DSH 会读取目录下的 `SKILL.md`；当前仓库已经放在 `.agents/skills/kivo-wiki/`。
- 如果 DSH 已配置 MCP，优先调用 MCP 工具；否则使用下面的 REST 接口。

MCP 客户端配置（以客户端实际格式为准）：

```json
{
  "mcpServers": {
    "kivo": {
      "url": "https://kivo.xiaowan.dpdns.org/mcp"
    }
  }
}
```

## 两种使用模式

### 快速查询

用户只问译名、实装状态、学校、生日等单项信息时：

1. `search_character` 找到 ID
2. `get_character` 取 `names,profile,intro`
3. 简明回答

### 创作模式

用户要写同人、角色扮演、剧情续写、角色分析、设定卡、对话、独白时：

1. `search_character` 找到 ID
2. `get_character` 取完整资料：

```json
{
  "id": 1,
  "sections": ["names", "profile", "intro", "lore", "related", "combat", "voices", "gallery"],
  "max_chars": 30000
}
```

3. 先整理角色设定卡，再开始写作
4. 写作时把设定卡当作约束，不要只依据一句简介

## 数据字段与创作用途

| 字段 | 内容 | 创作用途 |
|---|---|---|
| `names` | 国服、站内、日/韩/英/繁中译名 | 选对名字；需要外语称呼时使用 |
| `aliases` | 别称 | 日常称呼、绰号、他人叫法 |
| `profile` | 学校、年级、年龄、身高、生日、兴趣、声优、画师、武器、MomoTalk 签名 | 基础人设、日常话题、语气参考 |
| `intro` | 国服官方简介；未实装时回退站内简介 | 官方定位、第一印象 |
| `introSource` | `cn` / `wiki` / `none` | 判断简介是否为国服官方文案 |
| `lore` | 站内「杂项趣闻」等详细设定 | **创作核心**：经历、性格、习惯、矛盾、轶事 |
| `related` | 相关角色 | 人际关系、对话对象、剧情冲突 |
| `voices` | 有文本的语音台词，按类别分组 | **说话方式、语气、口头禅** |
| `gallery` | 图集分组标题和数量 | 外观、服装、形态线索 |
| `combat` | 稀有度、定位、攻击/防御类型、适应性、技能、基础数值 | 战斗描写、能力边界 |
| `release` | 国服/日服/国际服实装状态与日期 | 判断设定是否属于国服当前进度 |

### 详细设定从哪来

- 只读 `intro` 不够，必须读 `lore`。
- `lore` 里通常包含：人物经历、性格侧面、人际关系、喜好、绰号、剧情名场面、趣闻。
- `voices` 是模仿语气的第一手材料；优先选 3–5 句有代表性的台词。
- `related` 给出站内关联角色；它不一定覆盖 `lore` 里提到的所有人物。lore 提到的角色可以再按名字搜索。
- 如果用户要写互动，优先从 `related` 和 `lore` 里找关系对象，再查询对方资料。
- `gallery` 只给分组标题，不要凭空编造具体服装细节；图片需要视觉模型。
- `combat` 用于战斗场景，不要给角色安排设定之外的能力。

## 创作模式：角色设定卡

拿到完整资料后，先在内部整理成下面结构，再回答或写作。

```markdown
## 角色设定卡：{国服名}

### 身份
- 学校 / 年级 / 年龄：
- 身份 / 所属组织：
- 其他译名：

### 外貌与标志物
- 身高：
- 武器：
- 图集形态：
- 已知服饰线索：

### 性格
- 核心性格：
- 优点：
- 缺点 / 矛盾：
- 在意的事：

### 说话方式
- 语气：
- 口头禅 / 常用称呼：
- 代表性台词：
  - “……”
  - “……”

### 背景与经历
- 关键经历：
- 当前处境：
- 剧情名场面：

### 人际关系
- 与 A：
- 与 B：

### 能力
- 定位：
- 攻击 / 防御类型：
- 代表技能：

### 创作注意
- 国服状态：已实装 / 未实装
- 简介来源：国服官方 / 站内整理
- 缺失信息：
```

### 写对话或独白时

1. 从 `voices` 选 2–3 句，提炼句长、语气、称呼方式。
2. 从 `lore` 选 2–3 个具体设定点，不要只写空泛性格。
3. 从 `related` 选对话对象；没有相关角色时不要硬造关系。
4. 保留角色原有的矛盾或缺点，不要写成完美人设。
5. 二创可以合理延伸，但要区分「原作设定」和「创作补充」。

### 创作约束

- `intro` 是国服官方简介；`lore` 是站内整理，不是官方文案。两者都可用，但回答时要标注来源。
- `introSource: "wiki"` 表示没有国服官方简介，简介来自站内整理。
- `release.cn: false` 表示国服未实装，不要把该角色的内容当成国服当前既定设定。
- `related` 只包含已收录的国服角色；为空时不要编造关系。
- 图片无法直接读取，不要仅凭图集标题编造具体外观。
- 缺失数据直接说「暂无资料」，不要补完。
- 不要把整篇 `lore` 原样倒给用户；提炼成设定卡或融入创作。

## 快速查询模式

| 用户问什么 | 取什么 |
|---|---|
| 国服叫什么 / 所有译名 | `names.cn`，需要时加 `names.jp/kr/en/zh_tw` |
| 实装了吗 | `release.cn`、`meta.isCn`、Markdown 顶部「国服状态」 |
| 角色设定 / 剧情 | `intro` + `lore`，注意区分官方与站内整理 |
| 说话方式 | `voices` + `profile.momoTalk` |
| 人际关系 | `related` |
| 强度 / 技能 / 数值 | `combat` |
| 有哪些角色 | `list_characters` 或搜索 |

## 工作流

1. 先搜索：用用户给出的名字调用 `search_character`，不要直接猜 ID。
2. 如果没搜到，换用别名、日文名、英文名、韩文名或繁中名再试一次。
3. 找到 ID 后调用 `get_character`。
4. 快速查询只取必要 sections；创作模式取完整 sections 并设置 `max_chars=30000`。
5. 检查 `release.cn` / `meta.isCn` 或 Markdown 顶部的「国服状态」。
6. 默认用国服译名回答；用户问「所有译名」时再列出日/韩/英/繁中。
7. 区分 `intro` 和 `lore`：前者优先国服官方简介，后者是站内设定整理。
8. 回答末尾附上来源：`https://kivo.wiki/data/character/{id}`。
9. 缺失的数据直接说「暂无资料」，不要编造。

## 未实装角色

- 不要返回 404 或「查不到」；详情接口会返回资料和状态。
- `introSource` 是 `wiki` 时，说明简介不是国服官方文案。
- `combat` 为空时说明暂无战斗资料，不要补全。
- 典型例子：`千惠留`（ID 596）在国服未实装，应回答「千惠留尚未在国服实装，以下是站内资料」。

## 错误处理

- `404`：角色 ID 不存在，不要继续重试。
- `502`：上游暂时不可用，可以重试一次；仍失败则告知用户稍后再试。
- 搜索无结果：先换别名/其他语言名；仍无结果再说明未找到。

## 回答风格

- 用用户的语言回答。
- 先给结论，再列资料。
- 国服名优先，其他译名放在括号或列表中。
- 创作任务先给简短设定卡，再写正文。
- 明确区分「国服官方简介」和「站内设定整理」。
- 始终保留来源链接。

## 示例

### 示例 1：国服译名

用户问：「未花在国服叫什么？」

1. `search_character({ "query": "未花" })`
2. 取第一条 `id=1`
3. `get_character({ "id": 1, "sections": ["names", "profile"] })`
4. 回答：国服译名是「圣园 未花」，日服「聖園 ミカ」，国际服「Misono Mika」，繁中「聖園 彌香」。

### 示例 2：未实装角色

用户问：「千惠留实装了吗？」

1. `search_character({ "query": "千惠留" })`
2. 取 `id=596`
3. `get_character({ "id": 596, "sections": ["names", "intro", "profile"] })`
4. 回答：千惠留尚未在国服实装；站内资料显示她是崔尼蒂图书委员会副委员长，简介来自站内整理，不是国服官方文案。

### 示例 3：创作前取详细设定

用户问：「帮我写一段未花的独白。」

1. `search_character({ "query": "未花" })`
2. `get_character({ "id": 1, "sections": ["names", "profile", "intro", "lore", "related", "voices"], "max_chars": 30000 })`
3. 整理设定卡：
   - 身份：崔尼蒂综合学院三年生，原帕特尔领导人
   - 性格：表面开朗，内心有无法言说的烦恼
   - 关系：渚是发小，政治立场对立
   - 语气：轻快、亲昵，自称「我」，常用「老师」
4. 再写独白，避免写成纯甜或纯黑，保留她的矛盾。
5. 附来源：`https://kivo.wiki/data/character/1`

### 示例 4：按学校列角色

用户问：「崔尼蒂有哪些角色？」

1. `list_characters({ "school": "崔尼蒂", "limit": 20 })`
2. 汇总返回的国服译名；如果用户要完整名单，再分页获取。
