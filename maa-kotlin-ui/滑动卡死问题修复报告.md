# 滑动卡死 / 启动崩溃原因与解决方法

## 一、原因

### 1. MaaFramework 多途径点 Swipe 导致引擎卡死

`NonlinearSwipe` 曾通过 MaaFramework 执行以下形式的 Swipe：

```json
{
  "action": "Swipe",
  "end": [[x1, y1], [x2, y2], [x3, y3]],
  "duration": [d1, d2, d3]
}
```

MaaFramework v5.13.0-beta.2 执行 `end` 数组与 `duration` 数组组成的多途径点
Swipe 时，可能在 `ActionTask::run_impl` 后停止响应。单终点线性滑动和普通点击不受
影响，因此问题位于 MaaFramework 的多途径点 Swipe 执行路径。

### 2. MaaTaskerAddContextSink 导致引擎随机崩溃

为显示当前操作而注册 `MaaTaskerAddContextSink` 后，MaaFramework
v5.13.0-beta.2 的节点事件回调可能导致引擎随机崩溃。崩溃既可能发生在启动识别阶段，
也可能发生在滑动等任务执行阶段。

## 二、解决方法

### 1. 绕过 MaaFramework 多途径点 Swipe

修改 `app/src/main/java/com/maafw/naruto/maa/CustomActions.kt` 中的
`NonlinearSwipe`：

- 不再调用 MaaFramework 的多途径点 Swipe action；
- 改为 Kotlin 引擎层依次调用 `InputInjector.touchDown`、`touchMove` 和 `touchUp`；
- 在多个 `touchMove` 之间保留原有非线性轨迹和总持续时间。

这样可以保持原滑动效果，同时避开 MaaFramework 会卡死的执行路径。

### 2. 禁用 ContextSink

不要注册 `MaaTaskerAddContextSink`。当前操作信息如需展示，应由 App 侧解析
`maa_logs/maafw.log`，避免在 native 引擎中注册节点事件回调。

### 3. 使用当前 native 源码构建

`app/build.gradle` 已通过 CMake 接入 `app/src/main/native/`。标准 Gradle 构建会生成：

- `libbridge.so`
- `liblauncher.so`

不要将发行版 0.1 的同名旧文件放回 `app/src/main/jniLibs/arm64-v8a/`，以免重复打包
或误用历史产物。修改 native 源码后，应重新构建 APK，并在真机上回归验证启动、截图、
单指滑动和多点触控。
