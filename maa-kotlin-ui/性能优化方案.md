# MAAFW 火影忍者 —— 性能优化方案

> 目标：让脚本跑得更快（缩短单任务耗时、任务间间隔）更稳（降低卡死/异常概率）。
> 状态：🟢已实施 / 🟡待实施 / ⚪远期

---

## 一、已实施优化（🟢）

### 1. 引擎实例复用（收益最大，识别实时性三重保障）

- 任务**正常结束** → 保留 `resource/controller/tasker`，仅 `MaaTaskerClearCache` 清识别缓存；
- 下次任务直接 `MaaTaskerPostTask` 复用，**跳过 pipeline/image/OCR 模型重载**（省 2~5s/任务）；
- 任务**异常/启动失败** → 标记 `needRebuild`，下次任务自动销毁重建，保证稳定；
- **识别实时性**：清识别缓存 + 控制器重连 + 最新帧缓冲，日志记录帧号基线；
- **tasker 复用**：复用时不重建 tasker（避免旧 tasker 泄漏与 controller 竞争）。
- 设置 → 运行设置 →「引擎复用」开关可关。

### 2. focus 日志彩色显示（当前操作）

- 监听 `Node.Action.Starting` 动作事件（focus 携带于此），**异步发送 + 1s 去重**，不阻塞引擎；
- 日志面板解析 `[color:xxx]` 标签渲染彩色。

### 3. 后台挂机保障

- 引擎进程自持唤醒锁 + userActivity(4s) 防休眠 + requestDisplayPower(20s) 保亮；
- 任务期间自动临时保活（KeepAliveService）；
- Root 守护进程（设置开关，需 root）：常驻 root 进程调度定时任务，App 全死照跑；
- Root 唤醒应用（定时策略开关）。

### 4. 屏幕唤醒/解锁助手

- PowerManager.wakeUp 亮屏 + 无凭据锁屏解除 + 纯数字 PIN 自动输入。

### 5. 启动链路并行化

- 游戏预启动（等待首帧）与 MaaFramework 资源加载并行执行，重叠预启动与 OCR 模型加载耗时；
- 两者完成后再创建控制器，保留对画面就绪和资源加载完成的依赖。

---

## 二、待实施优化（🟡）

1. **识别算法瘦身**：模板匹配优先于 OCR、收紧 ROI；
2. **timeout/打断链** 优化、虚拟屏分辨率策略、线程优先级。

---

## 三、验证方法

1. **量化**：开启「帧率显示(Debug)」看游戏 FPS 与脚本识别频率（识别归零=卡死）；
2. **对比**：记录单任务耗时，引擎复用前后对比应省 2~5s；
3. **稳定性**：连续跑 10 次任务，观察 `status != 3000` 与虚拟屏残留。
